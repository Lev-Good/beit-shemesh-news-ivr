# חדשות בית שמש — מערכת הודעות קוליות

שרת Node.js לשלוחת ההקלטות `0/0/6` בימות המשיח. השרת שומר עותק מקורי בארכיון ימות, שולח את ההקלטה ל-Gemini לניסוח שמרני, יוצר קול עברי, משמיע תצוגה מקדימה ומפרסם בשלוחה `1` רק לאחר אישור מפורש של המקליט.

## דרישות

- Node.js 20 ומעלה.
- חשבון ימות המשיח והרשאת API. מומלץ מפתח API קבוע (`YEMOT_TOKEN`).
- מפתח Google Gemini API.
- תיקיות קיימות בימות: `0/0/6/archive`, `0/0/6/preview` ושלוחת פרסום `1`.
- Azure Speech נדרש רק אם בוחרים `TTS_PROVIDER=azure`. במצב ברירת המחדל `edge` אין צורך במפתח TTS.

## התקנה והרצה מקומית

```bash
npm ci
cp .env.example .env
```

ממלאים ב-`.env` את `YEMOT_TOKEN` (או `YEMOT_USERNAME` יחד עם `YEMOT_PASSWORD`) ואת `GEMINI_API_KEY`, ומריצים:

```bash
npm test
npm start
```

בדיקת בריאות: `http://localhost:3000/health`; בדיקת Keep-Alive: `http://localhost:3000/ping`.

## שלב 1 — בדיקה בשלוחת ניסוי בימות

1. יוצרים תיקיית `archive` ותיקיית `preview` תחת `0/0/6` (או מתאימים את משתני הנתיב), ומוודאים שלטוקן יש הרשאות קריאה, כתיבה, העתקה ומחיקה.
2. פותחים שלוחת ניסוי מסוג API. בקובץ `ext.ini` שלה מגדירים:

   ```ini
   type=api
   api_link=https://YOUR-SERVICE.onrender.com/yemot?secret=YOUR_WEBHOOK_SECRET
   ```

   אם השירות רץ בכתובת אחרת, מחליפים את הדומיין. הערך של `YOUR_WEBHOOK_SECRET` הוא אותו ערך שהוגדר ב-Render. אם לא מגדירים סוד (`WEBHOOK_SECRET` ריק), מסירים את `?secret=...`.

3. בודקים תחילה את תהליך ההקלטה, ההעתקה לארכיון, ההעלאה ל-preview והאזנה חוזרת. בדקו ש-Gemini לא הוסיף פרטים. הקשה `1` היא הפעולה היחידה שמפרסמת; `2` מנסחת מחדש את אותה הקלטה, `3` מתחילה הקלטה חדשה ו-`4` משמיעה שוב.
4. בדקו ידנית את סדר ההשמעה בשלוחה `1`. במצב `highest_first`, השרת בוחר שם מספרי אחד מעל המספר הקיים הגבוה ביותר, למשל `005.wav`. במצב זה, ודאו בהשמעת השלוחה שהקובץ בעל המספר הגבוה מושמע ראשון. אם ההשמעה מוגדרת מהנמוך לגבוה, בחרו `PUBLISH_ORDER_MODE=shift_to_zero` ובדקו היטב על שלוחת ניסוי; מצב זה מזיז קבצים קיימים קדימה ומפרסם חדש כ-`000.wav`.
5. בדקו גם דחייה, הקלטה שקטה, ניתוק בזמן עיבוד, כשל AI, בחירת פרסום ההקלטה המקורית ושתי שיחות בו-זמנית. לפני העברה לשלוחה פעילה, ודאו את שמות הפרמטרים ופורמט `UploadFile` בחשבון שלכם. API של ימות מחזיר זמני שמע ביחידות דקות בחלק מתצוגות התיקייה; הקוד דורש ש-`duration` בהעלאה יהיה מספר חיובי.

## שלב 2 — GitHub ו-Render

1. מעלים את תוכן התיקייה `news-ivr` למאגר GitHub (אפשר כמאגר עצמאי).
2. ב-Render בוחרים **New → Blueprint** ומצביעים על המאגר. אפשר גם ליצור Web Service עם `npm ci` כפקודת Build ו-`npm start` כפקודת Start.
3. מגדירים את משתני הסביבה לפי `.env.example`: לפחות `YEMOT_TOKEN` ו-`GEMINI_API_KEY`. Render יוצר `WEBHOOK_SECRET` אקראי מתוך `render.yaml`. מעתיקים את ערכו לתוך `api_link` בשלוחת הניסוי. ה-Blueprint מוגדר ל-Node 20 ותוכנית Free.
4. ממתינים לפריסה ובודקים את `https://YOUR-SERVICE.onrender.com/health` ואת `/ping`.

## שלב 3 — Keep-Alive

ב-cron-job.org יוצרים בדיקת HTTP מסוג GET לכתובת:

```text
https://YOUR-SERVICE.onrender.com/ping
```

מגדירים תדירות כל 10 דקות. תשובה תקינה היא HTTP 200 עם JSON קצר. בשכבת Free של Render השירות עדיין עשוי להיכנס לשינה או להיות מופעל מחדש; הקבצים הזמניים נשמרים בימות, ומצב השיחות/העבודות שבזיכרון יאבד בהפעלה מחדש. אין להסתמך על שרת זה כעל תור עיבוד עמיד.

## שלב 4 — העברה לשלוחה החיה ועדכון ניסוח

לאחר השלמת בדיקות הניסוי, מעדכנים את `api_link` בשלוחה החיה `0/0/6`, משאירים את התיקיות וההרשאות הנכונות, ומבצעים שיחת בדיקה. כדי לשנות את כללי הניסוח, עורכים את `prompts/rewrite.txt`, מעלים את השינוי ל-GitHub ומבצעים פריסה מחדש. אין צורך לשנות את קוד Gemini.

## זרימת הקבצים והפרטיות

- הקלטת המקור מועתקת לארכיון ימות לפני שליחה ל-Gemini. היא משמשת גם לניסוח חוזר ולמסלול פרסום מקורי במקרה כשל.
- קובץ Preview מועלה לימות ונמחק לאחר פרסום. מחיקה מחזורית מסירה קובצי preview ישנים מ-`PREVIEW_TTL_HOURS` (ברירת מחדל 24 שעות).
- אודיו שמורד לצורך עיבוד נשאר בזיכרון בלבד. קובץ TTS זמני של Edge נמחק לאחר הקריאה. Render Free משתמש בדיסק זמני שאינו משמש כארכיון.
- המגבלה היא לפי מספר טלפון ולפי כלל השיחות המקומי לתהליך. היא מתאפסת בהפעלה מחדש.
- `ARCHIVE_RETENTION_DAYS` מתועד ומוגדר כברירת מחדל ל-30 יום; המערכת אינה מוחקת את ארכיון ההקלטות המקוריות. יש לנהל את שימור הארכיון במדיניות נפרדת בימות.

## משתני סביבה מרכזיים

כל האפשרויות מופיעות עם הערות ב-`.env.example`. נתיבים ניתנים לשינוי באמצעות `YEMOT_PUBLISH_PATH`, `YEMOT_PREVIEW_PATH`, `YEMOT_ARCHIVE_PATH`, וקידומת API באמצעות `YEMOT_PATH_PREFIX` (ברירת מחדל `ivr2:`). ניסיונות העברת קבצים חוזרים לפי `YEMOT_RETRY_COUNT` ו-`YEMOT_RETRY_DELAY_MS`; ניסיונות AI/TTS לפי `AI_RETRY_COUNT` ו-`AI_RETRY_DELAY_MS`.

## בדיקות

הבדיקות משתמשות ב-`node:test` ובמוקים, אינן מתחברות לימות או לשירותי AI, וניתן להריצן כך:

```bash
npm test
```

הן מכסות פרסום במקביל ומספור, אישור מפורש, ניסוח מחדש של אותו מקור, הקלטה חדשה, ניתוק, כשל AI, מסלול פרסום הקלטה מקורית, הקלטה לא ברורה ושרשרת עיבוד Gemini/TTS.
